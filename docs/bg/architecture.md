# frost.bg — архитектура

*[In English](../en/architecture.md)*

Как е устроен проектът: мрежата се смята офлайн; един Worker сервира и API-то,
и статичните файлове; кешът е на ръба, изричен; страницата е чисти модули с
тънък DOM слой отгоре.

## Мрежата

`grid/grid.json` — **2 080 клетки** на стъпка **0,1°** над България, ~**1,6 MB**
неформатиран JSON. Смята се **офлайн**, обикновено веднъж годишно през януари,
не при заявка:

- `grid/fetch_cds.py` тегли от Copernicus CDS **по един NetCDF файл на
  година** (30 години дневен минимум на 2 м + един файл геопотенциал) —
  всяка година е отделна заявка, която застава на опашката на CDS (минути
  до часове, не дни);
- `grid/compute_grid.py --from-cds` чете тези файлове и смята всичките 2 080
  клетки за секунди, през сметката в `grid/frost_estimate.py` (виж по-долу).

И двата скрипта са само за поддръжка на мрежата: нито се пускат от Worker-а,
нито влизат в продукционния bundle. В runtime мрежата е чист JSON — Worker-ът
я импортира директно като JSON модул (`import grid from "../grid/grid.json" with {
type: "json" }`), тя се вгражда в бъндъла при `deploy`/`dev` и живее в
паметта на изолата, докато той е жив; никакво I/O при заявка не я чете от
диск или мрежа.

## Worker-ът

Един файл-рутер, `worker/index.js`: маршрутизира `/api/v1/*` към четирите
адреса и предава всичко останало на `env.ASSETS.fetch()` — статичните файлове
от `site/`. Логиката е разцепена по файлове:

- `frost.js` — чиста функция координати → най-близка клетка → тялото на
  отговора; без I/O;
- `geocode.js` — двата доставчика за търсене на място (Open-Meteo по
  подразбиране, Google при наличен ключ), с еднаква форма на отговора;
- `elevation.js` — доставчикът за височината на самата точка (Open-Meteo
  Elevation), с локален предпазител при throttling от доставчика;
- `texts.js` — двуезичните текстове на грешките и на посочванията на
  източника.

Никакви runtime зависимости — `package.json` държи само `wrangler` като dev
dependency. Защо е нарочно: вижте „Нови зависимости“ в
[`CONTRIBUTING.md`](../../CONTRIBUTING.md).

## Кешът

Cloudflare не кешира отговорите, които Worker сам генерира — трябва изричен
Cache API (`caches.default`) на ръба: `match` по нормализиран ключ, при miss
— смятане и `put`. Ключът носи ревизия (`rev=`, URL-кодирано): `версия на
приложението | датата на мрежата (grid.computed) | ефективната карта |
ефективният геокодер` — нов deploy, нова мрежа или друга карта/геокодер
получават нови ключове; старите записи просто изтичат по TTL, нищо не се
трие ръчно. `/api/v1/config` пази собствена ревизия отгоре — същата четворка
плюс превключвателя `ELEVATION`, защото само той засяга съдържанието ѝ.
`/api/v1/elevation` пък има съвсем отделна ревизия (`APP_VERSION |
"openmeteo-elevation"`) — не зависи от карта, геокодер или мрежа. Грешките
никога не се пишат в кеша (`Cache-Control: no-store`). Подробности и защо
всяко издание вдига версията — в [`operations.md`](operations.md).

## Страницата

`site/js/` е разделен на чисти модули без DOM — `stats.js` (сметките,
преписани дума по дума от `grid/frost_estimate.py`, за да не се разминат),
`history.js` (решава **какво** се показва) и `format.js` (форматиране на
числа, дати, URL-и). `chart.js` смесва чист модел (`chartModel`, `toCsv`,
тества се директно) с тънък слой рисуване върху SVG (`renderChart`,
`renderTable`) — двете изрично разделени в самия файл. `paint.js` е DOM
слоят за горните две карти с дати — функциите в него не решават нищо, само
пишат каквото им подадат; решенията са в `history.js`. `app.js` свързва
всичко това с истинския `document` — чете адреса,
вика четирите API адреса, инициализира картата (`map.js`) — самият той не
смята нищо, само рисува резултата от чистите модули.

## Средите

- **локално**: `npm run dev` = `npx wrangler dev` — истинският Workers
  runtime на `localhost:8787`, нищо не се качва в Cloudflare;
- **продукция**: `npx wrangler deploy`, на живо на <https://frost.bg>;
- **конфигурация**: `ELEVATION`, `GEOCODER`, `MAP` са публични променливи в
  `[vars]` на `wrangler.toml`; `GOOGLE_KEY` (сървърният ключ за
  геокодиране) е **тайна** — `wrangler secret put`, никога във
  `wrangler.toml`. `GOOGLE_MAPS_KEY` (за Google Maps JS в браузъра) е
  публична променлива нарочно — тя по природа се вижда от клиента и е
  защитена по HTTP referrer в Google Cloud, не по тайна.

## Тестовете

`npm test` пуска подред: тестовете на Worker-а (`node --test
"worker/*.test.js"`), на страницата (`node --test "site/js/*.test.js"`) и
питоновите тестове на мрежата и на CDS инструментите. `grid/grid.json` се
проверява при всеки пуск на Worker тестовете: 2 080 клетки, всички в
правоъгълника, датите `MM-DD` или `null`. `site/js/stats.parity.test.js`
сверява сметката в браузъра срещу записаното в `grid.json` за **всичките 2
080 клетки** (включително `null`-овете) — единственото, което пази
страницата и мрежата да не се разминат.

## Пътят на една заявка

```
браузър (site/js/app.js: fetch)
  → Cloudflare edge (frost.bg)
    → Worker (worker/index.js: fetch())
        │
        ├─ /api/* ?  не → env.ASSETS.fetch() → статичен файл от site/
        │
        └─ /api/* ?  да → маршрут по URL (frost | config | geocode | elevation)
              → ключ с rev → caches.default.match()
                    ├─ hit  → връща кешираното — готово
                    └─ miss → смята (frost.js / geocode.js / elevation.js)
                              → 200 JSON + Cache-Control (max-age/s-maxage)
                              → ctx.waitUntil(caches.default.put(…))
  → отговорът се връща по същия път до браузъра
→ site/js/app.js: paintPairs() / renderChart() / renderTable() рисуват резултата
```
