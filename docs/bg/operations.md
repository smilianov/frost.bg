# frost.bg — поддръжка: мрежата, локален пуск, deploy

*[In English](../en/operations.md)*

## Локален пуск

```bash
npm install
npm run dev
```

Отваря на [http://localhost:8787](http://localhost:8787) — `wrangler dev`
пуска истинския Workers runtime локално (нищо не се качва в Cloudflare).
Ключът за Google Geocoding/Maps (ако изобщо се ползва) е тайна, не
променлива: локално се задава като `GOOGLE_KEY=…` в `.dev.vars`
(в `.gitignore`, никога не се качва).

## Тестове

```bash
npm test
```

Пуска подред: тестовете на Worker-а (`node --test worker/`), на страницата
(`node --test site/js/`), питоновите тестове на мрежата
(`cd grid && python3 tests_frost.py && python3 tests_grid.py`) и тестовете
на CDS инструментите (`tests_cds.py` — през venv-а `.venv-cds`, ако го има,
иначе през системния `python3`). `grid/grid.json` се проверява при всеки
пуск на Worker тестовете: 2 080 клетки, всички в правоъгълника, всяка с
`typical`/`safe`, датите `MM-DD` или `null`. Същото се пуска в CI
(`.github/workflows/ci.yml`) при всеки push и pull request.

## Как се смята мрежата

`grid/grid.json` (показваната на сайта мрежа, 2 080 точки на 0,1°) се смята
**офлайн**, не при всяка заявка — вижте формата и правилата ѝ в
[спецификацията](../superpowers/specs/2026-09-14-frost-bg-design.md) (Р1).
Два инструмента я пълнят; никой от двата не се пуска от Worker-а и не влиза
в продукционния bundle.

### Основният път: Copernicus CDS (ERA5-Land)

Първоизточникът на мрежата. Едно теглене на година за цялата област — без
квоти по точка, за разлика от Open-Meteo (виж по-долу защо това има
значение).

**Еднократна подготовка на машината на собственика:**

1. Безплатна регистрация в [Copernicus CDS](https://cds.climate.copernicus.eu/).
2. Приемане на лицензите на **двата** набора данни от собствените им
   страници — иначе теглянето пада с грешка за неприет лиценз:
   - [`derived-era5-land-daily-statistics`](https://cds.climate.copernicus.eu/datasets/derived-era5-land-daily-statistics)
     (дневния минимум);
   - [`reanalysis-era5-land`](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-land)
     (геопотенциала, за височината на клетката).
3. Ключът на CDS в `~/.cdsapirc`, по инструкциите на CDS страницата на
   собствения профил.
4. `cdsapi` и `netCDF4` не са зависимости на самия проект — живеят в
   отделна venv, за да не тежат на Worker-а и сайта:
   ```bash
   cd grid
   python3 -m venv .venv-cds
   .venv-cds/bin/pip install -r requirements-cds.txt
   ```

**Теглене:**

```bash
cd grid
.venv-cds/bin/python fetch_cds.py --out cds
```

30 години дневен минимум + една заявка за геопотенциала. Всяка година е
отделна заявка към CDS — заявката застава на опашка (по думите на самия
скрипт: минути до часове, зависи от натоварването на CDS в момента);
`--parallel N` (по подразбиране 3) тегли до N години едновременно, всяка в
своя нишка със свой `cdsapi.Client()` (`--parallel 1` за последователно
теглене, ако предпочиташ). **Продължава след прекъсване:** вече изтеглените
файлове се прескачат, недовършените `.part` файлове се презаписват — пусни
пак същата команда. Резултатът каца в `grid/cds/` (в `.gitignore` — не
влиза в репото; няколко МB на файл).

**Смятане, с кръстосана проверка спрямо старата Open-Meteo проба:**

```bash
.venv-cds/bin/python compute_grid.py --from-cds cds --cross-check cells.jsonl
```

Чете NetCDF файловете и смята всички 2 080 точки за секунди (за разлика от
часовете при Open-Meteo, защото няма заявка по точка). `--cross-check` очаква
`cells.jsonl` от по-ранен Open-Meteo пробег (виж по-долу) и за всяка обща
клетка печата разликата в дни между двата източника за `typical`/`safe`
(напролет и наесен); в края — обобщение (брой сравнени клетки, най-голямата
разлика). Разлика над **10 дни** за която и да е клетка (или `null` срещу
стойност) е **предупреждение** — изходният код на командата е **1** вместо
0, което значи: спри и прегледай преди да пуснеш `git add`/`commit`, не е
автоматичен провал за CI (кръстосаната проверка не е част от `npm test`).

**Кога:** веднъж годишно, през януари — когато предната календарна година
вече е напълно в ERA5-Land.

**Морските клетки:** ERA5-Land покрива само сушата — клетките над Черно
море (около 178 от 2 080, по източния ръб на правоъгълника) излизат с
`null` дати вместо температури; височината им (геопотенциалът) си я има,
дефиниран е навсякъде. Очаквано, не грешка.

### Помощният път: Open-Meteo (проби и кръстосана проверка)

```bash
python3 grid/compute_grid.py                  # истинският пробег, точка по точка
python3 grid/compute_grid.py --synthetic       # правдоподобна мрежа без мрежа, за разработка
python3 grid/compute_grid.py --finish          # сглобява grid.json от вече готовия cells.jsonl
```

Не иска venv, не иска регистрация — за проба на отделни точки, или за
попълване на `cells.jsonl`, което после `--cross-check` сравнява срещу
резултата от CDS. Всяка точка е отделна заявка към архива на Open-Meteo;
пауза между заявките (`--pause`, по подразбиране 1 s); 429 или мрежова
грешка → до 3 опита на точка с нарастващо изчакване. **Квотата е тясна:**
измерено — един час стига за около 64 точки, едно денонощие за около 128
(от 2 080 общо), затова трети пореден 429 спира целия пробег веднага
(квотата явно е изчерпана) вместо да продължава да я удря; всяка сметната
точка вече е записана в `grid/cells.jsonl` (в `.gitignore`), така че
пускането на командата пак по-късно продължава оттам, не преизчислява.
`--finish` само сглобява `grid.json` от каквото има в `cells.jsonl`, без
нови заявки.

## Какво още липсва за публичния deploy

Локалната работа не чака на нищо от това:

- регистрация на домейна `frost.bg` и DNS в Cloudflare — стъпка на
  собственика;
- `wrangler login` (връзка с акаунта в Cloudflare) и `wrangler deploy`
  (качва Worker-а и статичните файлове; засега само локално с
  `wrangler dev`); custom domain на `frost.bg` в настройките на Worker-а;
- тайната `GOOGLE_KEY` в продукция: `wrangler secret put GOOGLE_KEY`
  (никога във `wrangler.toml`);
- променливите `GEOCODER`, `MAP`, `GOOGLE_MAPS_KEY` за продукционната среда
  (в момента са зададени само за локално `[vars]` в `wrangler.toml`; без
  собствен `[env.production]` продукция ще ползва същите — прегледай ги
  преди първия deploy);
- лимит на заявки към API-то — правило в Cloudflare (WAF / rate limiting),
  не код в Worker-а;
- deploy от GitHub Actions при сливане в `main` — записано за по-късно
  (фаза 2 в спецификацията), CI засега само тества.
